# Правила для Claude — «Призванный: Башня Гачи»

Основные правила проекта — в `README.md` (раздел «Правила работы»), они действуют всегда. Здесь — как работать **экономно по лимиту**.

## Экономия лимита (главное)

Каждый прочитанный файл, вывод команды и картинка тратят лимит. Поэтому:

1. **Никогда не читать целиком:**
   - `index.html` (≈17 МБ, собранный файл) и `android/app/src/main/assets/index.html`;
   - картинки в `assets/`, `docs/reference/` — смотреть только конкретную, когда без неё нельзя;
   - `docs/archive/*` — только `grep` по номеру версии, если правда нужно;
   - большие файлы: `src/template.html` (240 КБ), `src/ui2.js`, `src/ui3.js`, `src/*.css`, `docs/ART_*.md` — сначала `grep -n`, потом читать только нужный кусок (offset/limit, `sed -n A,Bp`).
2. **Начало сессии:** прочитать `PROGRESS.md` (он короткий — держать его таким). `docs/GDD.md` и `docs/ui/*.md` — только разделы, которые касаются текущей задачи.
3. **Вывод команд — коротко:** `npm test 2>&1 | tail -8`, `npm run build 2>&1 | tail -3`, `git diff --stat` вместо полного diff. Не печатать base64, JSON с картинками, длинные логи.
4. **Правки — точечно** (Edit по кусочку), не переписывать большие файлы целиком и не перечитывать файл после правки.
5. **Скриншоты:** один на экран для сверки с макетом; повторный — только после исправлений. Не делать серии скриншотов «на всякий случай».
6. **Без субагентов** и без параллельных «исследований» — всё делать самому, по шагу.
7. **Симуляции баланса** (`npm run sim`, `godsim`, `yearsim`) — только когда задача про баланс; длинные (`yearsim`) — только по просьбе пользователя.
8. **Ответы пользователю — коротко:** что сделано, ссылка, что дальше. Без пересказа шагов и кода.
9. **Если задача большая** — сначала короткий план в 3–5 пунктов и вопрос с вариантами, потом работа. Не начинать переделку, которую потом придётся откатывать.

## PROGRESS.md — держать коротким

- В конец — запись о версии в 2–4 строки: что сделано, решения пользователя, важные числа.
- Когда `PROGRESS.md` больше ≈25 КБ — перенести старые версии в `docs/archive/PROGRESS_<от>-<до>.md`, оставив «Как работать с кодом», «Следующий шаг» и последние ~10 версий.
- Раздел «Следующий шаг» обновлять, а не дописывать: убирать сделанное.

## Порядок одного шага

1. Сделать одну фичу/правку.
2. `npm test` (кратко), при правке интерфейса — `npm run build` и один скриншот.
3. Обновить `PROGRESS.md`, коммит + пуш.
4. Обновить тестовую ссылку (см. README). APK — только по прямой просьбе.
